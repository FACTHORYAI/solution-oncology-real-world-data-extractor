# Sample data

Every file below is synthetic: invented oncology notes and the rows extracted from them,
generated by [`generate_sample.py`](generate_sample.py) from sentence templates and small
oncology vocabularies (eight cancer types, their sites, drugs, procedures, symptoms and
treatment side effects). No real patient, note or record is used. Licence: CC0-1.0. The folder
is about 150 KB, far under the 5 MB per file and 20 MB per folder limits.

| File | What it is | Where it came from | Licence | Synthetic |
| --- | --- | --- | --- | --- |
| `notes.parquet` | 150 oncology notes: note_id, text. Breast (21), lung (21), colon and rectum (21), pancreas (14), prostate (16), kidney (13), lymphoma (27) and melanoma (17) | Notes n001 to n005 are hand-written, the other 145 are generated by `generate_sample.py` | CC0-1.0 | yes |
| `icd10_hcc.parquet` | 909 findings (353 cancers and metastases, 512 symptoms, 44 treatments) each coded to ICD-10-CM with its billable flag and HCC score: note_id, chunk, entity, icd10_code, code_name, billable, hcc_score, confidence | Written by the generator from the same templates as the notes | CC0-1.0 | yes |
| `billable_codes.parquet` | The nearest billable ICD-10-CM code per finding, with its oncology category and the rank of the candidate it came from | Produced by `extract_oncology_entities` from the recorded answers | CC0-1.0 | yes |
| `rxnorm_drugs.parquet` | 244 drug mentions resolved to RxNorm (26 drugs) | Written by the generator from the same templates as the notes | CC0-1.0 | yes |
| `procedure_codes.parquet` | 203 procedure mentions coded to ICD-10-PCS (46 codes): note_id, chunk, procedure_code, procedure_name, code_system, confidence | Written by the generator from the same templates as the notes | CC0-1.0 | yes |
| `assertions.parquet` | 865 assertion statuses, one per cancer or symptom mention: Present (576), Absent (179), Someone_else (56), Hypothetical (24), Possible (22), Conditional (8) | Written by the generator from the same templates as the notes | CC0-1.0 | yes |
| `temporal_relations.parquet` | 352 temporal relations between clinical events: AFTER (272), BEFORE (53), OVERLAP (27) | Written by the generator from the same templates as the notes | CC0-1.0 | yes |
| `bodypart_relations.parquet` | 352 relations between an organ and a procedure (201) or a problem (151) | Written by the generator from the same templates as the notes | CC0-1.0 | yes |
| `graph_nodes.parquet` | 199 knowledge-graph nodes (88 Condition, 46 Procedure, 39 Body_Part, 26 Drug), one row per node | Built from the tables above by the `build_knowledge_graph` job | CC0-1.0 | yes |
| `graph_edges.parquet` | 1,562 knowledge-graph edges, one fact per row, with note evidence and character span (865 `ASSERTION`, 266 `AFTER`, 201 `PERFORMED_ON`, 150 `INVOLVES`, 53 `BEFORE`, 27 `OVERLAP`) | Built from the tables above by the `build_knowledge_graph` job | CC0-1.0 | yes |

Every row of the extracted tables carries the `note_id` of the note it came from, and the
graph's `evidence_document_id` holds the same value. The notes carry no patient and no date.

The notes mix a finding the patient has (Present), one the note denies (Absent: "denies chest
pain", "no evidence of distant metastasis"), one it is unsure about (Possible: "the scan suggests
possible bone metastases"), one that is only a risk (Hypothetical: "counselled about the risk of
neutropenia"), one that depends on something happening first (Conditional: "antiemetics to use if
nausea develops") and one that a relative has (Someone_else: "her mother was treated for breast
cancer"). They name stages, regimens, procedures and temporal phrases such as "two weeks after the
last cycle of carboplatin and paclitaxel". A few findings are coded to an ICD-10-CM category that
is not billable, so `billable_codes` has to fall back to a more specific code.

`icd10_hcc`, `rxnorm_drugs`, `procedure_codes`, `assertions`, `temporal_relations` and
`bodypart_relations` are what a text model would return for each note. Here they are exact by
construction, because they come from the same templates as the notes; they are not the output of a
model. `tests/recorded_answers.json` replays them, so the six extraction jobs run without a model
and give back these tables, row for row.

How real the codes are:

- The ICD-10-CM codes are real, public codes with descriptions as the generator's author knows
  them. They have not been checked against the current release of the code set.
- The HCC scores are illustrative. They follow the pattern of the CMS-HCC relative factors per
  cancer group, and the mapping from code to group has not been verified.
- The RxNorm codes are illustrative identifiers and are not verified against RxNorm.
- The procedure codes are illustrative seven-character identifiers in ICD-10-PCS shape. They are
  not verified against the vocabulary. ICD-10-PCS is published by CMS and is in the public
  domain. CPT is not included because of its licence.

A production run resolves every code against the real vocabularies through the text model.

To regenerate (the same seed always gives the same files):

```
uv run python data/generate_sample.py
```
